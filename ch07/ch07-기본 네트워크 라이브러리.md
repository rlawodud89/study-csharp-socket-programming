# ch07 과제. 기본 네트워크 라이브러리 구현

계층형 아키텍처를 바탕으로 기본적인 네트워크 라이브러리를 구현. 최소한 다음 기능을 포함

- TCP 소켓 연결 관리
- 메시지 프레이밍 처리
- 간단한 패킷 직렬화/역직렬화
- 세션 관리 기능

## 서버

- 패킷 구조: length (4바이트) + PacketId (2바이트) + Body (N바이트)
- 모든 패킷은 `IPacket` 인터페이스를 상속하여 구현
- 패킷 ID는 `PacketId` enum으로 정의

#### 소켓 통신 계층

`TcpServer`

- 네트워크 연결 수립 및 종료
- 클라이언트 연결 수락 루프 실행
- 연결 수락하면 세션(`TcpSession`) 생성하고 실행
- 서버 전체에서 사용할 `SessionManager`와 `PacketProcessor`를 관리

#### 메세지 프레이밍 계층

`MessageFramer`

- TCP 바이트 스트림에서 개별 메시지 경계 구분
- 메시지 분할 및 병합 처리
- Length를 먼저 읽어 전체 패킷 크기를 확인
- length + PacketId + Body 형태로 패킷 조립

#### 세션 관리 계층

`TcpSession`

- 클라이언트 연결 세션 관리, 연결 해제 처리
- 수신 루프 실행해 패킷을 지속적으로 수신
- `MessageFramer`를 이용해 완전한 패킷을 구성한 뒤 `PacketProcessor`를 통해 역직렬화
- 각 세션은 하나의 `MessageFramer`를 보유하여 독립적으로 메시지 프레이밍 수행

`SessionManager`

- 현재 서버에 연결된 모든 세션 관리
- `TcpSession` 생성 시 `SessionManager` 에 등록, 연결 종료 시 등록 해제
- 서버(`TcpServer`) 하나당 하나의 `SessionManager` 보유 → 해당 서버에 접속한 세션 관리

#### 패킷 처리 계층

`PacketSerializer`

- 패킷 객체를 Length + PacketId + Body 형태의 바이트 배열로 직렬화

`PacketProcessor`

- 역직렬화 헬퍼 클래스
- `Dictionary<PacketId, Func<IPacket>>`를 이용해 패킷 ID와 패킷 타입을 관리
- 역직렬화 시 패킷 ID 확인해서 해당하는 타입의 패킷 객체로 생성
- 서버(`TcpServer`)마다 하나의 `PacketProcessor`를 생성하며, 모든 `TcpSession`이 이를 공유하여 사용
