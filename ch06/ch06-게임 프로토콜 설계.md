# ch06 과제. 게임 프로토콜 설계

간단한 2D 게임에 필요한 프로토콜을 설계

- 플레이어 이동, 채팅, 아이템 습득 등 최소 5개 이상의 패킷 유형을 정의
- 패킷의 구조와 직렬화/역직렬화 방법을 구현

## 서버

ch05 과제로 구현했던 SAEA 에코 서버를 기반으로 구축

- 클라이언트로부터 패킷 수신받으면 직렬화해 콘솔에 출력한 후, 역직렬화해 클라이언트에게로 송신
- 패킷 유형에 따라 다른 방식으로 화면 출력

**패킷 유형 정의**

`PacketHeader` (패킷 길이, 패킷 ID)를 가진 `IPacket` 인터페이스 정의, 상속받아 각 유형의 패킷 정의

- 채팅 메시지 (`ChatMessagePacket`): 보낸 사람, 메시지 내용
- 플레이어 이동 (`MovePacket`): 이동 후 좌표 X, Y
- 아이템 습득 (`ItemPickupPacket`): 습득한 아이템 ID
- 아이템 판매 (`ItemSellPacket`): 판매한 아이템 ID, 판매 수량
- 공격 (`AttackPacket`): 공격 대상 ID, 피해량

**직렬화**

- `IPacket` 내에 패킷 페이로드를 직렬화하는 메서드 정의 (멤버 필드들을 순서대로 바이트로 씀)
- 패킷 객체를 받으면 임시 길이, 패킷 ID 바이트로 쓴 후 패킷 페이로드를 `IPacket` 의 직렬화 메서드로 씀
- 다 쓴 이후에 전체 패킷 길이를 계산하고, 임시 길이로 써둔 필드에 업데이트

**역직렬화**

- `PacketProcessor` 라는 클래스 정의: 패킷 ID에 따른 패킷 클래스 관리
    - Dictionary를 통해 패킷 ID에 따른 패킷 클래스 타입 저장
    - 모든 패킷 클래스(`IPacket` 을 상속받은 클래스)를 초기화할 때 Dictionary로 등록
- `IPacket` 내에 패킷 페이로드를 역직렬화하는 메서드 정의 (바이트를 순서대로 읽어서 멤버 필드 채움)

역직렬화 과정

1. 바이트에서 헤더를 읽어서 패킷 ID 확인
2. Dictionary를 통해 해당하는 패킷 클래스 타입 알아냄
3. 패킷 객체 생성
4. 해당 클래스에 정의되어 있는 페이로드 역직렬화 메서드로 헤더 뒷부분 읽어서 패킷 멤버 채움
5. 패킷 반환

**메시지 프레이밍**

패킷마다 길이를 읽고 구별해서 받아와야 하므로 메시지 프레이밍 적용 → `MessageFramer` 클래스 사용

- `MessageFramer` : 버퍼에 데이터를 누적하고 길이에 맞게 바이트를 잘라서 반환하는 기능 정의
    - 패킷 분할로 인해 바이트가 조각나서 들어온다면 반환하지 않고 버퍼에 누적 → 다음 바이트가 들어올 때 누적된 바이트 함께 확인해서 길이 맞으면 함께 반환
- 각 SAEA 객체가 `MessageFramer` 를 하나씩 갖고, 이를 사용해 메시지 프레이밍
    - UserToken에 `MessageFramer` 저장하고 SAEA 객체에 지정
    - 각 클라이언트를 담당하는 수신 SAEA 객체에서 메시지 프레이밍 동시 가능

## 클라이언트

- 1~5번 키를 누르면 해당하는 타입의 패킷이 서버로 전달
- 서버로부터 패킷을 받으면 역직렬화로 패킷 타입 확인 → 타입에 맞게 다른 내용 콘솔에 출력
- 패킷 유형, 직렬화/역직렬화 방식 서버와 동일 → 모든 데이터 일관되게 해석
