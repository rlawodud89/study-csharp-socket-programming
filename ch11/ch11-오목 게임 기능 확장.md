# ch11. 오목 게임 기능 확장

**관전 기능**

현재 진행 중인 게임을 다른 사용자가 관전할 수 있는 기능

- 관전자 목록 관리
- 관전자에게 게임 상태 동기화

**게임 기록 재생 기능**

이전에 진행된 게임의 기록을 저장하고, 다시 재생할 수 있는 기능 구현

- 각 턴마다 돌 위치 기록
- 기록된 게임 목록 조회
- 선택된 게임 재생 (턴별로 진행)

## 관전 기능

(OmokSpectaor_Server)

- `GameRoom` 에서 `List<Player>` 로 관전자 목록 관리
- `JoinSpectatorRequest` , `LeaveSpectatorRequest` 로 클라이언트가 관전 참가/퇴장 메시지 전송
- `MessageHandler` 에서 클라이언트 메시지 처리
    - `JoinSpectatorRequest` → 참가하고자 하는 `RoomId` 확인, 해당 `GameRoom` 의 관전자 목록에 클라이언트 추가, 현재 게임 보드 전송
    - `LeaveSpectatorRequest` → 퇴장하고자 하는 `RoomId` 확인, 해당 `GameRoom` 의 관전자 목록에서 클라이언트 제거
- 돌을 놓을 때마다(게임 상태 바뀔 때마다) 브로드캐스팅을 관전자에게도 보냄 → 게임 상태 동기화

## 게임 기록 재생 기능

(OmokRecord_Server)

- `GameRoom` 에서 `GameRecord` 로 현재 게임의 기록 저장 (게임 한 판의 기록)
- 돌을 놓을 때마다 `MoveRecord` 를 `GameRecord` 에 추가, `GameRecord` 는 `List` 로 돌 배치 기록 관리
- `GameRecordManager` 에서 모든 `GameRecord` 관리, 게임 한 판이 종료되면 `GameRecord` 를 저장하고 새로운 `GameRecord` 사용
- `ReplayListRequest` 로 클라이언트가 기록된 게임 목록 조회 요청, `ReplayListResponse` 로 서버가 게임 목록 조회 전송
- `ReplayRequest` 로 클라이언트가 선택된 게임 재생 요청, `ReplayResponse` 로 서버가 선택된 게임의 돌 배치 기록 전송
- `MessageHandler` 에서 클라이언트 메시지 처리
    - `ReplayListRequest` → 클라이언트의 `PlayerId` 확인, 해당 클라이언트가 참가했던 게임의 기록들을 `GameRecordManager` 에서 가져와서 `ReplayListResponse` 에 담아 전송
    - `ReplayRequest` → 선택한 게임의 `GameId` 확인, 해당 게임의 기록을 `GameRecordManager` 에서 가져와서 `ReplayResponse` 에 돌 배치 기록 담아 전송
- 클라이언트는 `ReplayResponse` 에서 받은 돌 배치 기록을 순서대로 화면에 출력 → 턴별로 진행된 게임 재생
